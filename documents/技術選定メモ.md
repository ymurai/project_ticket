# 技術選定メモ

> **最終結論**: `TypeScript + Remix + Prisma + PostgreSQL` (開発は SQLite) を中心に据え、CI/CD は GitHub Actions → Fly.io。理由と代替案は以下に整理。

---

## 1. ランタイムと言語

| 候補                       | 推しポイント                                | 主な懸念                      |
| ------------------------ | ------------------------------------- | ------------------------- |
| **TypeScript (Node 20)** | OSS エコシステム最大・型安全・フルスタック JS で画面⇄API 共通 | Cold-start が Go/Deno より遅い |
| **Python 3.12**          | データ処理に強い・Django/FastAPI 成熟            | フロント別途 JS 必須・二段ホスティング     |
| **Go 1.22**              | 単一バイナリ・高速・Fly.io 好相性                  | テンプレエンジンや ORM 学習コスト       |

結論: **TypeScript**。

---

## 2. フレームワーク

| 案              | 長所                                           | 懸念                   |
| -------------- | -------------------------------------------- | -------------------- |
| **Remix** (推奨) | サーバアクションでフォーム→DB→メールを 1 ファイルに凝縮／SSR と静的のバランス | コミュニティ規模は Next.js 未満 |
| Next.js(+tRPC) | App Router + Server Actions で似た構成／Vercel 親和  | レイヤ境界が混在しやすい         |
| Django         | 管理画面が強い                                      | JS フロント分離で二重管理       |

結論: **Remix**。

---

## 3. データアクセス

* **Prisma ORM**：DB 方言を隠蔽、`transaction()` で同時予約競合を解決。
* 代替: Drizzle ORM / TypeORM

---

## 4. インフラ

| 層       | 推奨                        | 補足                           |
| ------- | ------------------------- | ---------------------------- |
| Runtime | Fly.io Machines           | 東京リージョン無料枠 + Postgres Add-on |
| CDN     | Fly 直配信 or Cloudflare     | Remix が Asset Header を自動設定   |
| メール     | Resend                    | Free 3k/月、API Key だけ         |
| 監視      | Fly Metrics + Uptime Kuma | `/status` エンドポイント ping       |

---

## 5. テスト & CI/CD

* **Vitest**: Logic/ORM Unit Test
* **Playwright**: Purchase→メール→Check-in E2E
* **CodeQL**: SAST (GitHub)
* **GitHub Actionsフロー**

  1. `build-test` → Lint + Unit/E2E
  2. `docker-image` → GHCR Push
  3. `deploy-fly` → `fly deploy`

---

## 6. 代替スタックと乗り換えコスト

| 案               | 追加工数       | 損益分岐点                    |
| --------------- | ---------- | ------------------------ |
| Astro + FastAPI | API サーバ分追加 | 静的比率が高く PWA を極限まで軽くしたい場合 |
| Laravel 11      | TS→PHP 学習  | 劇団側に PHP 人材が多い場合         |
| Supabase (BaaS) | Prisma不要   | DB 接続情報を OSS に含めたくない場合   |

---

## 結論

1. **TypeScript + Remix + Prisma + PostgreSQL** が MVP→拡張まで滑らか。
2. "フロント SSG / バックエンド別言語" を好むなら **Astro + FastAPI** が次点。
3. 将来 GraphQL 開放や座席マップ等大型機能が来ても Prisma & Remix ならスケール可能。
